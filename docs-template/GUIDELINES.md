# Documentation guidelines

These are general guidelines, not strict rules. A rough document now beats a perfect one never.

## The ones that matter most

- Write the purpose first so readers know if they are in the right place
- Keep one topic per document to avoid confusion and make navigation easier
- Update or delete a document when it goes stale to keep everything useful

## Writing

Use short sentences and plain words. Define a term the first time you use it. Say who the document is for.

## Files and names

Use lower-case words joined with hyphens, such as p-bit-core.md, so links work everywhere. Pick a name that says what the document is about. Put images in an assets folder next to the document.

## Formatting

Start from blank-template.md and keep its HUBA header and licence footer, so every document is instantly recognisable. Use one H1 per document. Use headings so readers can scan. Put captions on tables and figures and mention them in the text. Fence code with its language. Use ISO dates YYYY-MM-DD.

## Keeping it up to date

Set Status to Draft, Review or Approved, whichever fits. Change the Date when you make a real change. Small fixes need no ceremony.

## When in doubt

Copy a nearby document and follow its style.
